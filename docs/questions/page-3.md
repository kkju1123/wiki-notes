# Questions · 第 3 页

## Q1: 请总结 LLM API 调用的最基本代码模式，不同厂商的差异主要在哪些方面？

最基本模式有四步：导入 SDK、创建客户端、调用接口发送请求、从响应中读取模型输出。伪代码为：`import sdk； client = sdk.Client(api_key=...)； response = client.xxx(model=..., input=...)； print(response.output)`。不同厂商的差异主要是 SDK 包名、客户端类名、API 地址、方法名、请求参数格式和 response 结构不同。例如 Claude 用 `messages.create` 和 `messages`，OpenAI 用 `responses.create` 和 `input`，DeepSeek 用 OpenAI 兼容接口加 `base_url`。底层思想一致：通过 SDK 封装 HTTP 请求，调用指定 LLM 并解析返回结果。


## Q2: 基础 LLM API 调用与 Agent / Tool Calling 有什么区别？Tool Calling 的基本流程是什么？

基础调用是“用户输入 -> LLM -> 文本输出”，模型只能生成文字，不能真正执行搜索、查数据库或操作系统。Tool Calling 允许模型输出结构化的工具调用指令，由程序去执行实际工具，再把结果返回给模型继续推理。基本流程是：用户输入 -> 模型判断需要调用工具 -> 输出工具名和参数 -> 程序执行工具 -> 把结果作为消息回传 -> 模型综合结果生成最终回答。当模型能自主循环调用工具、规划步骤时，就逐步进入 Agent 范畴。学习路线一般从基础 SDK 调用开始，再到 Structured Output、Tool Calling，再到 Agent 和 RAG 等系统。


## Q3: 请总结 API、SDK、client、API Key、response、model、base_url 这些概念之间的关系和核心数据流。

API 是服务端提供的程序接口；SDK 是用来方便调用 API 的开发工具包；client 是 SDK 创建的通信对象；API Key 是调用 API 的身份凭证；model 是真正要调用的 LLM；base_url 指定 API 请求发往哪台服务器；response 是 API 返回给程序的结果对象。核心数据流是：Python 代码 -> SDK -> client -> API -> LLM 模型 -> API -> response -> 程序解析输出。理解这组关系后，Claude、OpenAI、DeepSeek 等调用本质上都是“用某个 SDK 构造 API 请求，调用指定模型，拿到 response 后取出模型输出”。

## Q4: 请介绍并深挖你的两个实习项目（项目背景、技术难点、个人贡献与收获）。

回答框架：先一句话说明业务背景、团队规模和你的职责，再挑 2~3 个最有技术含量的模块展开，比如高并发、数据一致性、复杂业务抽象或性能优化。每个点按“问题背景→为什么难→可选方案→为什么选这个→落地结果→效果数据→复盘缺陷”来讲。如果面试官追问，重点解释设计取舍、异常场景、可观测性和可改进点，不要只背结论。建议提前准备架构图、核心接口/表结构、监控指标和线上问题案例，这样能体现工程师的系统思维。


## Q5: 实现一个通用智能体（Agent）要考虑哪些功能点？

通用智能体通常包含：1) 模型接入层，支持多模型、流式输出、超时重试、切换和成本控制；2) 规划/推理模块，支持 ReAct、Plan-and-Execute、状态机等模式；3) 工具调用框架，包含 schema 定义、参数校验、权限、错误重试和超时处理；4) 上下文与记忆，包括短期对话、长期记忆、摘要和向量检索；5) 知识接入，如 RAG、知识库检索；6) 安全护栏，如敏感信息过滤、操作越权控制、Prompt 注入防护；7) 可观测性，包括链路追踪、日志、指标和回放；8) 人机协同，关键操作需确认；9) 评测与回归，保证模型和流程变更可验证。常见追问：上下文窗口有限怎么办、工具调用失败如何恢复、记忆如何分层设计。


## Q6: 请说明 HTTPS 端到端链路。

从客户端输入 HTTPS 地址开始：1) DNS 解析域名得到服务器 IP；2) 建立 TCP 连接；3) 进行 TLS 握手，ClientHello 协商版本、密码套件、SNI，ServerHello 返回证书；4) 客户端校验证书链、有效期、域名匹配和吊销状态；5) 双方协商对称密钥，TLS1.3 通常使用 ECDHE 等具备前向安全性；6) 之后 HTTP 数据用对称密钥加密传输，保证机密性和完整性；7) 服务器处理请求后通过同一加密通道返回，连接可 keep-alive 复用或关闭。关键点：证书链校验防止中间人攻击，HSTS 避免 HTTP 降级，TLS1.3 减少握手 RTT。


## Q7: 手撕二叉树的右视图（给定二叉树，返回从右侧看到的节点值）。

推荐两种实现：BFS 层序遍历，每轮处理当前层所有节点，把最后一个节点值加入结果；DFS 使用根→右→左遍历，维护当前深度，当深度等于结果长度时加入该节点，表示该层第一个被访问的最右节点。两种方法时间复杂度都是 O(n)，空间复杂度 O(n)。注意空树返回空列表。常见追问：左视图只需根→左→右；如果要求打印底视图、俯视图，则需要用哈希记录横向偏移。


## Q8: 请介绍并深挖你的一个实习项目（项目背景、技术难点、个人贡献与收获）。

单项目深挖更看重你的系统设计能力和落地深度。建议按“业务背景→总体架构→个人负责模块→最难问题→方案对比→结果指标→复盘反思”展开。重点讲一个数据一致性、性能、稳定性或复杂业务抽象的问题，说明你如何定位、为什么不用简单方案、如何验证和上线。面试官常追问：如果重新做会怎么改、高量级下哪里会坏、如何监控和回滚。准备时最好有量化结果和一个可讨论的缺陷，这样能体现真实性和成长性。


## Q9: 手撕前缀树（Trie）的实现，包括插入、查找和前缀匹配。

Trie 节点通常包含 children，可用 HashMap 或 26 长度数组，以及 isEnd 标记。insert 逐字符遍历，没有节点就创建，末尾置 isEnd；search 逐字符走，最后返回 isEnd；startsWith 只判断路径是否存在。每个操作时间复杂度 O(L)，L 为字符串长度；空间与公共前缀有关。工程上可优化为压缩前缀树、双数组 Trie，或在节点上存词频。常见追问：如何删除节点、中文字符如何处理、子节点少时怎么节省内存。


## Q10: 前缀树（Trie）有哪些应用场景？

常见场景：搜索框/输入法自动补全、拼写检查与纠错、敏感词和广告词过滤、搜索引擎关键词建议、IP 路由最长前缀匹配、词频统计、T9 输入法、基因序列前缀匹配等。相比哈希表，Trie 支持按前缀查询、公共前缀压缩和顺序遍历；缺点是内存占用可能较大，尤其是字符集较大时，需要做压缩优化。


## Q11: 应用层和传输层的职责分别是什么？

应用层面向用户和业务，定义应用语义和交互流程，常见协议有 HTTP、DNS、SMTP、FTP，负责编解码、业务逻辑、会话管理和鉴权等。传输层提供端到端进程间通信，通过端口标识进程，负责分段、重组、差错校验；TCP 还提供可靠传输、流量控制、拥塞控制和连接管理，UDP 提供低时延尽力而为传输。一句话：应用层管作什么业务，传输层管怎么把数据可靠/高效地送到目标进程。


## Q12: 从浏览器请求到服务机房的全链路是什么？

完整链路：浏览器解析 URL 后查本地缓存/HSTS，DNS 递归解析得到 IP，可能指向 CDN；建立 TCP 连接，HTTPS 再做 TLS 握手；请求经过 CDN/边缘节点，命中缓存则直接返回；未命中进入机房入口，经过防火墙、负载均衡、反向代理/网关做鉴权、限流、路由；后端服务处理时可能调用缓存、数据库、消息队列或其他服务；响应沿原路返回，浏览器解析 HTML/CSS/JS 并渲染。优化点包括 DNS 预解析、连接复用、CDN 缓存、TLS 会话复用、服务链路超时/熔断/降级。


## Q13: 什么情况下会把某个能力做成 skill？什么时候做成 tool？实习中遇到过这样的问题吗？

tool 是原子能力，通常是模型通过 function calling 调用的单个函数或 API，输入输出结构化、粒度小、无业务状态；skill 是更高层封装，包含提示词、工具集合、知识、流程、权限和输出规范，能完成一类端到端任务。判断标准：只一个动作、无状态、可被频繁调用就做成 tool；需要多步、组合多个工具/知识、有固定业务 SOP 或需要复用为完整能力就做成 skill。实习中我会把“查询订单”做成 tool，而把“售后问题处理”做成 skill，因为它要串联查询订单、检查时效、执行退换货多个步骤并带业务规则。


## Q14: LangChain 和 LangGraph 的区别是什么？

LangChain 是 LLM 应用开发框架，封装了模型、提示词、检索、工具和 Chain/LCEL，适合快速搭建线性或简单 DAG 流程。LangGraph 是基于状态图的运行时框架，把任务建模为带 state 的节点和边，支持循环、条件分支、子图、checkpoint 和 human-in-the-loop，适合复杂 Agent 和多智能体。主要区别：LangChain 的 Chain 偏向顺序执行，复杂循环和状态管理较弱；LangGraph 显式建模控制流，能暂停、恢复和回放。常见选择：简单链用 LCEL，复杂循环或 Agent 用 LangGraph。


## Q15: 除了 ReAct，还有哪些常见的模型交互/推理模式？

常见模式有：Plan-and-Execute，先制定整体计划再逐步执行，适合长任务；Reflection/Reflexion，执行后进行自我批评并改进；Function Calling，模型直接按 schema 调用工具，不强制显式推理；AutoGPT 式自主循环，目标驱动持续规划-执行-评估；Tree of Thoughts/Graph of Thoughts，多路径搜索和回溯；Self-Ask，把复杂问题拆成子问题逐步求解；Multi-agent 协作，多个智能体分角色协作。面试官常追问 ReAct 和 Plan-and-Execute 的区别：ReAct 逐步推理执行，Plan 先生成全局计划，长任务更稳定但可能过度计划。


## Q16: 请说明 SSE（Server-Sent Events）的底层实现原理。

SSE 基于 HTTP 长连接，客户端使用 EventSource 发起普通 GET 请求，请求头携带 Accept: text/event-stream，服务器返回 Content-Type: text/event-stream 并保持连接不断。服务端按格式推送数据，通常为 `data: {...}

`，也可带 event、id、retry 字段；浏览器收到分块数据后触发对应事件。它本质是单向流，只能服务器推客户端，基于标准 HTTP，天然经过代理，并支持自动重连和通过 Last-Event-ID 恢复。实现时要注意关闭缓冲或定期发送注释/心跳防止代理超时。对比 WebSocket：SSE 单向、文本、HTTP 友好；WebSocket 全双工、二进制，更适合实时双向通信。
