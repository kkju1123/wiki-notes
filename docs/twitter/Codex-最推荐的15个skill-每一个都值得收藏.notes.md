# Codex 最推荐的15个skill，每一个都值得收藏！

*原文: [https://x.com/XiaohuiAI666/status/2095130302381494664](https://x.com/XiaohuiAI666/status/2095130302381494664) · 来源: twitter · 生成时间: 2026-09-17T01:42:47.584223+00:00*

## 背景

Codex 本身像一个聪明但缺乏固定工作流程的实习生：模型能生成代码，但不一定知道什么时候该先做计划、什么时候该看 CI 日志。Skill 机制的出现，就是把这些“什么时候该做什么、怎么做”的方法论固化成可插拔、可复用的技能包，避免每次都要在 prompt 里重复教学。它背后对应 Agent 工程从一次性指令到资产沉淀的转变。

## 痛点

如果没有 Skill，AI 在复杂开发任务中容易凭通用经验直接猛写代码，导致方向性返工；调试时也常靠“猜一个原因改一版试试”的低效循环。同时，团队最佳实践无法沉淀，换个工具或项目就要重新教一遍。

## 解决办法

Skill 的本质是一个包含 SKILL.md 的文件夹，SKILL.md 通过 frontmatter 声明 name 和 description，并在正文里写清触发条件、执行步骤、原则和可选脚本。Codex 启动时只把每个技能的 name 和 description 预加载进系统提示，模型根据任务需要再判断是否调用。这相当于给实习生一柜子工具和对应 SOP：不需要把所有工具都摊在桌上，但每个工具上贴着标签。官方精选技能覆盖开发流程、浏览器自动化、部署、安全审查等高频场景，社区技能则通过 npx skills add 按需安装。关键约束是不要装太多，因为技能列表本身占用上下文窗口，过多会导致选择失准。

## 关键代码示例

```markdown
---
name: create-plan
description: 在编写代码前先生成实现计划，避免方向性返工
---

# Create Plan

## 触发条件
当用户提出新功能或复杂改动时。

## 执行流程
1. 阅读需求，识别约束和未知点。
2. 输出 plan.md：目标、改动点、测试策略、风险。
3. 用户确认后才开始写代码。

## 原则
- 不直接产出实现代码；
- 计划必须具体到文件/函数级别；
- 遇到模糊需求先提问。
```

这段 SKILL.md 体现了一个最小技能的结构：frontmatter 中的 name 和 description 是 Codex 预加载并用于技能选择的标签，正文则描述触发条件和执行 SOP。它对应前面提到的“先规划后编码”，通过用流程约束模型的输出顺序，而不是靠 prompt 口头提醒。把这样的文件放进 ~/.codex/skills/ 后，Codex 在遇到新功能需求时就可能调用 create-plan。

## 关键流程

1. 用 $skill-installer 查看官方精选区里有哪些技能，确认名称和用途。
2. 按需安装：官方技能使用 $skill-installer <skill-name>，社区技能常用 npx skills add <repo>。
3. 安装后询问 Codex“你现在有哪些技能”，确认技能已被预加载和识别。
4. 若要在多个 Agent 间复用，把 SKILL.md 所在目录复制或软链到 ~/.codex/skills/、~/.claude/skills/ 等对应目录。

## 关键点

- Skill 的本质是“SOP + 可选脚本”，通过 SKILL.md 的 frontmatter 注入系统提示，因此它是可迁移资产而非平台绑定配置。
- 技能不是越多越好，每个技能都会消耗上下文窗口，过多会导致模型在相近技能间选择失准，应按高频痛点精选。
- 官方内置三件套 skill-creator、skill-installer、plugin-creator 是生产工具，说明 OpenAI 更鼓励攒技能，而不是只做市场。
- 开发流程类技能覆盖“计划-测试-调试-CI-评论-日志”闭环，能有效压制 AI 的冲动编码和方向性返工。
- book-to-skill 和 cangjie-skill 把书籍或视频蒸馏成可调用技能，代表知识资产化的新方向。
- SKILL.md 是 agentskills.io 开放标准，同一份技能可迁移到 Claude Code、Codex、WorkBuddy、Cursor，因此技能库是长期资产。

## 对比与权衡

- 相比 WorkBuddy 的社区技能大市场，Codex 官方精选数量少但在质量、一致性和维护上更可控；不过生态丰富度不如社区市场。
- 相比 MCP 这类外部工具协议，Skill 更像内部 SOP 插件，实施成本低、迁移简单；但动态连接外部系统能力不如 MCP。
- 相比直接把整本书 PDF 塞进上下文，book-to-skill 按章节加载，token 消耗可降到 1/24 至 1/51；但需要预先结构化，不能即传即问。
- 相比 book-to-skill 的“读书查询”，cangjie-skill 更偏向“方法论上岗干活”，产出原子化能力卡；但更依赖高质量输入文稿。

## 面试可能会问

**问: 什么是 Codex Skill？它和普通 prompt 有什么区别？**

Skill 是可复用的结构化 SOP，通过 SKILL.md 的 frontmatter 预加载进系统提示；普通 prompt 是一次性指令，无法沉淀为资产。

**问: 为什么 skill 安装太多会导致模型选择失准？**

每个技能占用上下文窗口，技能列表变长后模型需要做更多选择判断，容易在相近技能之间串扰；应控制数量，按使用频率精选。

**问: SKILL.md 为什么能迁移到 Claude Code、Cursor？**

这些工具遵循 agentskills.io 开放标准，都认 SKILL.md 的 frontmatter 和目录结构；迁移只需复制或软链。

**问: book-to-skill 为什么能把 token 消耗降到整本 PDF 的 1/24 到 1/51？**

它将书拆成章或主题，按需加载，只把当前相关章节注入上下文，而不是全量文本；结构化还能减少无效检索。

**问: last30days 和普通搜索有什么不同？**

它并行搜索 Reddit、X、YouTube、Hacker News、Polymarket，按真实互动和真金白银下注排序，聚合的是“人”而不是编辑；用于获取近期社区情绪，而不是权威解释。

## 适用场景

- 高频开发场景：让 AI 先规划再编码、自动修复 CI、批量处理 PR 评论。
- 团队标准化：把团队最佳实践沉淀为技能，跨成员和工具复用。
- 知识蒸馏：把书籍、视频、长文转成可调用技能，作为个人知识库。
- 线上排障与情报收集：用 Sentry 查生产错误，用 last30days 做趋势或舆情调研。
