# 如何通过模型路由优化 AI Agent 的成本、速度与质量

*原文: [https://medium.com/towards-artificial-intelligence/how-to-optimize-ai-agent-cost-speed-and-quality-with-model-routing-73ea640ad1d2](https://medium.com/towards-artificial-intelligence/how-to-optimize-ai-agent-cost-speed-and-quality-with-model-routing-73ea640ad1d2) · 来源: medium · 生成时间: 2026-09-16T14:43:33.619672+00:00*

## 背景

AI Agent 通常由规划器、模型、工具、记忆和评估器等多个组件组成，不同步骤的复杂度差异极大。如果对所有步骤都使用同一个最强模型，会带来不必要的 token 成本和延迟；如果全部使用小模型，又可能因质量不足导致大量重试。模型路由正是为了解决这种“一刀切”模型选择带来的资源浪费和质量风险。

## 痛点

没有模型路由时，简单任务使用大模型会显著增加成本和响应时间，复杂任务使用小模型则容易出现推理错误、校验失败和多轮重试。开发者缺乏清晰的升级依据，往往只能凭经验选模型，难以在预算内稳定交付高质量结果。

## 解决办法

模型路由把“选择哪个模型”从一次性决策变为可观测、可校准的动态策略。核心思想是先分析每个 Agent 步骤的复杂度和质量要求，为每个步骤设定可量化的评估阈值，默认走最便宜的轻量模型，当校验失败、评估分数低于阈值或任务复杂度超过预设阈值时逐级升级到更强模型。每次升级都基于任务信号（如 schema 校验失败、矛盾输出、置信度过低），而不是盲目重试，最终在保证质量的前提下最小化总成本。

## 关键代码示例

```python
class ModelRouter:
    def __init__(self, accept_score=0.85, max_retries=3):
        self.accept_score = accept_score
        self.max_retries = max_retries

    def route(self, task):
        model = 'gpt-4o-mini'  # 默认最便宜的模型
        for _ in range(self.max_retries):
            result = call_model(model, task)
            score = evaluate(result, task)  # 评估器给出质量分数
            if score >= self.accept_score and valid(result):
                return result, model
            # 未达标则升级模型
            if model == 'gpt-4o-mini':
                model = 'gpt-4o'
            elif model == 'gpt-4o':
                model = 'gpt-5.6-luna'
            else:
                break  # 最强模型仍失败，触发受控回退
        return None, 'fallback/human_review'  # 有界重试后回退
```

这个路由器的核心是“默认省钱，未达标再升级”。首先用最便宜的 mini 模型，每次调用后用评估器计算质量分数并检查输出是否有效；不满足阈值时升到中等模型，再失败才用最强模型。重试有上限，最强模型失败后返回受控失败或人工复核，避免无限消耗。这对应文中提到的 escalation 与 fallback 策略，阈值需要根据真实业务数据校准。

## 关键流程

1. 梳理 Agent 各组件（规划、模型、工具、记忆、评估）的资源消耗与质量影响，明确哪些步骤可以降级。
2. 为每个步骤或任务类型设定量化评估标准和最低可接受分数，避免凭感觉决定升级。
3. 默认路由到成本最低的模型，如 GPT-4o-mini，处理常规、结构化任务。
4. 在质量分数低于阈值、校验失败或任务复杂度超过预设阈值时，逐级升级到更强模型，如先 GPT-4o 再 GPT-5.6 Luna。
5. 对每条路由持续记录成本、响应时间、验证成功率和任务质量，用代表性测试集调整升级阈值和重试预算。

## 关键点

- 模型路由的本质是用更细颗粒度的调度替代全局模型选择，让每个步骤只支付必要的模型成本，这是优化整体性价比的关键。
- 评估器和质量阈值是路由策略可运行的基础，没有可量化的质量信号，升级决策就变成拍脑袋，容易引入更多重试成本。
- 升级信号应该来自具体失败证据（如 schema 校验失败、关键字段缺失、矛盾输出或低于阈值的评估分），而不是模糊的“感觉复杂”。
- 必须有有界重试和受控回退机制：最强模型也失败时要返回失败或转人工，而不是无限重试导致成本失控。
- 阈值和模型选择必须基于目标工作负载的真实数据校准，不能直接套用其他场景的经验值，因为任务分布和评估标准差异很大。
- 模型路由与多 Agent 架构不是互斥的：在单 Agent 内部使用路由可以显著降低协调成本，只有当任务差异大到需要完全独立上下文时再考虑拆多 Agent。

## 对比与权衡

- 相比对所有任务都用同一个最强模型的单模型架构，模型路由在平均成本、响应速度和资源利用率上更好，但需要额外维护评估器和校准阈值，系统复杂度更高。
- 相比多智能体架构，模型路由在保持单个 Agent 简单性和减少协调 token 开销上更好，但在任务类型极度分散、需要隔离上下文或并行执行时，多智能体可能更灵活。
- 相比静态规则路由（仅基于任务类型写死 if-else），基于评估分数和失败历史的动态路由更能适应数据分布变化和长尾任务，但更难调试和离线验证。

## 面试可能会问

**问: 模型路由中如何避免升级策略导致成本反而更高？**

要设置有界重试和受控回退，并且用真实数据校准升级阈值。如果升级频繁但成功率没有显著提升，说明初始模型选择或评估阈值不合理，需要回看日志分析失败原因，而不是继续增加重试次数。

**问: 如何评估一个模型路由策略的好坏？**

不能只看成本，要同时跟踪平均延迟、验证成功率、最终任务质量分数和人工介入率。最好在代表性测试集上对比不同策略的 Pareto 曲线，找到在满足质量目标下成本最低的配置。

**问: 模型路由与多智能体架构有什么区别？**

模型路由是在同一个 Agent 执行流中动态切换模型，共享上下文和状态，协调成本低；多智能体是多个 Agent 分别承担不同角色，通过消息或共享记忆协作，适合需要隔离上下文或并行执行的任务，但会带来额外的通信和 token 开销。

**问: 为什么不能只用任务复杂度作为路由信号？**

复杂度难以客观度量，容易主观偏差；更可靠的信号包括 schema 校验失败、关键字段缺失、矛盾输出、评估器分数低于阈值等可观测失败证据。复杂度和失败历史可以作为辅助信号，但不宜作为唯一依据。

**问: 上下文成本在模型路由中如何处理？**

不同模型对长上下文的计费差异很大，路由决策前应评估当前上下文长度和压缩策略。对于包含大量检索内容、对话历史的请求，即使用强模型也应先做上下文压缩或摘要，否则 token 成本会抵消模型选择带来的收益。

## 适用场景

- 高并发的客服机器人：大部分标准化问题用便宜模型，少数复杂投诉或政策咨询自动升级到强模型。
- RAG 问答系统：对检索到的证据充足、置信度高的问题使用小模型，对推理要求高或与知识库冲突的问题升级模型。
- 自动化工作流 Agent：在规划、工具调用后处理和最终总结等不同步骤分别设置路由策略，降低整体执行成本。
- 代码生成或审查 Agent：简单样板代码生成用轻量模型，复杂重构或跨文件逻辑分析升级到强模型。
