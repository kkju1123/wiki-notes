# 云沙箱预装环境参考

*原文: [https://platform.claude.com/docs/en/managed-agents/cloud-sandboxes-reference](https://platform.claude.com/docs/en/managed-agents/cloud-sandboxes-reference) · 来源: web · 生成时间: 2026-09-20T07:23:08.324449+00:00*

## 背景

云沙箱是为 AI Agent 提供隔离执行环境的基础设施，运行在 Anthropic 托管的 Linux 容器中。传统上 Agent 要先检测环境、安装依赖，既慢又容易出错；预置工具链让 Agent 拿到任务就能直接执行。统一的标准镜像也提高了任务结果的可复现性。

## 痛点

如果没有这类预装环境，Agent 每次运行代码、操作数据库或处理文档前都要先安装依赖，增加延迟和失败概率。自建环境还可能因版本不一致导致行为不可预期；不了解这些预置能力，也容易重复安装已有组件，浪费时间和磁盘。

## 解决办法

Anthropic 维护统一的 Ubuntu 24.04 x86_64 容器镜像，按语言、数据库、系统工具、文档处理等类别预装好常用组件，并通过环境变量和默认路径减少配置。数据库服务器默认不运行，Agent 需要时显式启动，避免无谓占用资源。浏览器自动化使用预装 Playwright 与 Chromium 配对，并设置 PLAYWRIGHT_BROWSERS_PATH，让库能自动找到浏览器。整体类似于一台已经配好常用工具的“拎包入住”开发机，而不是空白 Linux 主机。

## 关键代码示例

```bash
# 无需安装，直接使用预装工具链
python3 -c 'import numpy, pandas; print("data libs ok")'
node -e 'console.log(process.version)'

# 启动预装数据库（默认不运行）
pg_ctlcluster 16 main start
redis-server --daemonize yes

# 使用预装浏览器自动化
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto('https://example.com')
    print(page.title())
    browser.close()
PY
```

这段 bash 演示了云沙箱的核心价值：无需安装即可直接使用语言运行时、数据库和浏览器自动化。先调用 python3/node 验证预置语言和库；再按需启动 PostgreSQL/Redis，因为镜像中服务只是安装好但默认不运行；最后通过预装 Playwright 启动 Chromium，依赖环境变量 PLAYWRIGHT_BROWSERS_PATH 自动定位到 /opt/pw-browsers。如果另装 Playwright，浏览器路径不一致可能导致失败。

## 关键流程

1. 确认任务运行在 cloud 环境；self-hosted 沙箱由你的 worker 镜像决定，不适用本参考。
2. 按语言选择默认版本和包管理器，例如 Python 默认使用 python3 解释器，并已安装 NumPy、pandas 等数据科学库。
3. 需要使用数据库时，先显式启动服务；PostgreSQL 和 Redis 默认只是安装好，不会自动运行。
4. 浏览器自动化直接使用预装 Playwright 包，不要另装版本，避免找不到预置的 Chromium。
5. 根据任务网络需求选择环境：API 创建默认 unrestricted 网络，Claude Studio 默认 limited。

## 关键点

- 云沙箱是隔离 Linux 容器，运行在 Anthropic 托管基础设施上，执行环境可替换且不直接接触用户主机。
- 预装多语言运行时与包管理器让 Agent 无需安装步骤即可运行代码，减少首步延迟和网络依赖。
- 数据库服务器默认不启动，这是容器化镜像的常见做法：避免无用进程占用内存、端口冲突，按需启动更节省资源。
- Playwright 与 Chromium 放在 /opt/pw-browsers，并通过 PLAYWRIGHT_BROWSERS_PATH 关联，因此必须使用预装包而不是随意安装其他版本。
- 沙箱默认上限为 8 GB 内存、10 GB 磁盘，设计任务时需考虑大型依赖或数据集的配额。
- 网络模式区分 API 创建和 Claude Studio，影响外网访问能力，需要根据任务类型选择。

## 对比与权衡

- 相比 self-hosted sandbox，云沙箱提供统一、预配置的标准环境，可复现性更好，但运行在 Anthropic 基础设施上，自定义能力和数据驻留可能受限。
- 相比用户从零构建 Docker 镜像，云沙箱省去维护镜像和安装步骤，但预装版本固定，若需要特定版本组合可能仍要额外安装或改用自托管。
- 相比常规本地开发容器，云沙箱以 Agent 为第一用户，预置浏览器自动化、文档转换等面向任务的工具，但交互式开发体验可能不如本地 IDE 容器。

## 自测问题

**问: 为什么 PostgreSQL/Redis 服务器默认不运行？**

容器镜像通常只安装服务但不启动，因为启动会占用内存、可能绑定固定端口造成冲突，而且并非所有任务都需要数据库。Agent 需要时显式启动，符合按需分配资源的原则。

**问: Playwright 浏览器为什么不放 PATH，而用环境变量？**

浏览器二进制路径可能与系统默认路径冲突，单独放在 /opt/pw-browsers 便于版本管理和授权；设置 PLAYWRIGHT_BROWSERS_PATH 让 Python/Node 包自动发现。若自己安装 Playwright，它会期望在默认缓存或指定路径放浏览器，可能找不到。

**问: cloud sandbox 和 self-hosted sandbox 的核心区别？**

cloud 由 Anthropic 托管并提供标准预置镜像；self-hosted 运行在你自己的 worker 上，环境由你提供的镜像决定，可定制但一致性需要自己保证。安全边界和网络策略也不同。

**问: 如果 Agent 需要安装额外依赖怎么办？**

沙箱提供包管理器（pip/npm/cargo 等），可以安装，但受磁盘 10GB、内存 8GB 和网络策略限制；如需固定复杂依赖，最好构建自定义镜像或用 self-hosted。

**问: 预装 LibreOffice、pandoc、tesseract 这些文档处理工具体现了什么设计意图？**

说明沙箱面向 Agent 的常见任务不只是运行代码，还包括 Office 转换、PDF 处理、OCR 等非结构化数据处理，预装它们能减少安装系统级依赖的麻烦。

## 适用场景

- 需要 Agent 即时代码生成与执行验证的对话式编程场景。
- 数据处理与文档转换任务：用 Python 数据科学库、pandoc、LibreOffice、PDF 工具快速处理文件。
- 浏览器自动化测试或网页抓取：直接调用 Playwright + Chromium。
- 需要临时 PostgreSQL/Redis 验证数据库逻辑或缓存方案的原型开发。
