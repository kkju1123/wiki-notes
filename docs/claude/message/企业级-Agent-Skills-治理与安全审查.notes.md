# 企业级 Agent Skills 治理与安全审查

*原文: [https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise) · 来源: web · 生成时间: 2026-09-20T06:20:20.608535+00:00*

## 背景

Agent Skills 将指令、脚本和资源打包，让 Claude 在特定场景下获得专精能力。但企业内部或第三方技能一旦被加载，就相当于引入了可执行代码、提示词和工具权限，单靠平台默认安全不够。因此企业需要一套治理机制，解决供应链风险、权限滥用和技能冲突问题。

## 痛点

没有系统治理时，恶意或低质量技能可能执行任意脚本、读取敏感文件并通过网络外传数据；多个技能还可能互相抢触发，导致代理在错误场景激活，输出质量下降。缺少版本和审批记录也会使故障难以回滚和审计。

## 解决办法

把每个 Agent Skills 当作受控资产进行准入：先按风险指标分级，重点检查代码执行、指令操纵、MCP 引用、网络访问、硬编码凭据和文件系统范围；再执行人工审查清单，确认脚本行为、外部跳转和数据流。可在 claude.ai/Cowork 开启自动化扫描作为补充，但 API 上传路径仍需人工审查加版本固定。部署前必须用 3-5 个代表查询评估触发准确性、隔离性、共存性、指令遵循和输出质量，并跨 Haiku/Sonnet/Opus 验证。最后通过版本固定、灰度发布和持续监控做生命周期管理。

## 关键代码示例

```python
import os

SUSPICIOUS_SECRET_TERMS = ['api_key', 'token', 'password']
SUSPICIOUS_NET_TERMS = ['requests.get', 'urllib', 'curl', 'http://', 'https://']

def scan_skill(path):
    findings = {'secrets': [], 'network': []}
    for root, _, files in os.walk(path):
        for f in files:
            if not f.endswith(('.md', '.py', '.sh', '.js', '.txt')):
                continue
            full = os.path.join(root, f)
            with open(full, 'r', errors='ignore') as fh:
                text = fh.read().lower()
            if any(term in text for term in SUSPICIOUS_SECRET_TERMS):
                findings['secrets'].append(full)
            if any(term in text for term in SUSPICIOUS_NET_TERMS):
                findings['network'].append(full)
    return findings

```

这段脚本递归扫描技能目录中的文档和脚本，用常见敏感词做静态初筛，分别标记疑似硬编码凭据和网络访问模式。它对应企业审查清单里的高风险指标，但静态扫描不能发现运行时行为和混淆后的代码，因此必须配合沙箱执行与人工审查。

## 关键流程

1. 按风险指标给技能分级：检查代码执行、指令操纵、MCP 引用、网络访问、硬编码凭据、文件系统访问和工具调用。
2. 完成人工审查清单：阅读全部文件、沙箱运行脚本、检查对抗性指令、网络调用、凭据、工具命令和重定向目标。
3. 在有条件的情况下开启 Skill and plugin security scanning，覆盖 claude.ai 和 Cowork；API 部署继续依赖人工审查。
4. 部署前要求作者提交 3-5 个代表性查询，覆盖应触发、不应触发和歧义边界，并跨模型测试。
5. 按规划、创建审查、发布、监控、退役管理生命周期，版本固定并在指标恶化时更新或下线技能。

## 关键点

- 企业治理要区分平台本身是否安全和具体某个技能是否可信，前者看平台安全文档，后者必须逐个审查。
- 高风险指标中，代码执行、MCP 引用和网络访问会显著扩大攻击面，即使技能描述正常，也必须检查其脚本和指令真实行为。
- 自动化扫描是可选项且只覆盖 claude.ai/Cowork，API 上传、存量技能以及 CMEK/ZDR/HIPAA 等配置可能不在扫描范围内，因此不能替代人工清单。
- 部署前评估触发准确性、隔离性、共存性、指令遵循和输出质量，能防止技能互相抢触发或指令被错误执行。
- 技能效果依赖模型，必须在企业实际使用的 Haiku/Sonnet/Opus 上分别验证，不能只测最强模型。
- 版本固定是回滚和审计的基础；没有固定版本的技能在更新时可能绕过既有审查。

## 对比与权衡

- 相比纯人工审查，自动化扫描能更快发现隐藏的恶意代码和外传行为，但覆盖面有限且难以理解语义意图，因此只能作为补充而非替代。
- 相比直接把技能开放给员工，集中审批和风险分级的治理更安全、可审计，但会降低迭代速度，适合企业高风险环境。
- 相比只评估单技能质量，增加共存性评估能避免技能之间的触发冲突，但需要建立跨技能测试用例，成本更高。

## 自测问题

**问: 如果一个技能目录里有 Python 脚本，你会如何审查？**

先把它归为高风险，阅读 SKILL.md 和脚本全部内容；在沙箱运行脚本，确认输出与描述一致；检查网络访问、文件路径和硬编码凭据；再看指令是否要求 Claude 在敏感数据上执行该脚本。若涉及外部传输，必须拒绝或改用最小权限和密钥管理。

**问: 自动化扫描为什么不能覆盖 API 上传的技能？**

官方扫描集成在 claude.ai/Cowork 的企业设置中，Skills API 和 Console 上传路径不经过该扫描器；此外存量技能和 CMEK/ZDR/HIPAA 配置也可能被排除。API 部署应把技能目录放进 Git，在 CI 中做静态扫描，配合人工清单和版本固定。

**问: 如何判断一个技能的触发是否准确？**

要求作者提供 3-5 个代表查询，包括应触发、不应触发和歧义边界；在 Haiku/Sonnet/Opus 上分别运行，统计触发率和误触发率。失败时优先收紧 description 或调整触发条件，而不是修改业务指令。

**问: 多个技能共存时发生冲突怎么办？**

建立共存性评估，检查是否存在 description 过宽导致抢占触发；可以合并重叠技能、约束各自适用范围或建立技能目录和命名规范。必要时用小流量灰度观察冲突是否消失。

**问: 企业如何做技能版本管理和回滚？**

要求技能使用不可变版本或 git commit hash 锁定，发布前重新走安全和评估流程；生产环境只引用固定版本，上线时灰度发布并监控输出质量，问题时可快速回滚到上一版本。

## 适用场景

- 企业从内部团队或第三方引入多个 Agent Skills，需要统一做安全准入和审批。
- 在 Claude Enterprise 中为员工开放自定义技能上传，需启用扫描并设置审批门禁。
- 平台团队建设内部技能目录，需要评估技能触发冲突、输出质量和跨模型表现。
- 需要满足安全审计或合规要求，记录技能版本、审查结果和上线审批历史。
